# MedRAG local learning plan

I read the project files. I didn't run anything or change any code. Every command below is for you to run yourself, when you're ready.

**What the project does:** it reads medical guideline PDFs and PubMed abstracts, splits them into chunks, and stores them as vectors in Qdrant. When you ask a question, it finds the most relevant chunks and gives them to OpenAI. OpenAI writes an answer, and the app returns it with evidence and sources. You can use it through a CLI, a FastAPI API, or a Streamlit UI.

**Skip all of this (it's only for AWS):** `.github/`, `infra/`, `deploy/`, `scripts/`, `docker-compose.prod.yml`, `docs/aws_deployment_guide.md`.

## Phase 0: Big picture (about 1 hour, reading only)
1. Read [README.md](MedRAG_live/README.md), especially the 3 diagrams: architecture, indexing flow and query flow.
2. Open [MedRAG_Project_Report.pdf](MedRAG_live/output/pdf/MedRAG_Project_Report.pdf) and [flow.excalidraw](MedRAG_live/flow.excalidraw). You can view the .excalidraw file on excalidraw.com.
3. Learn the basic ideas if they're new to you: **RAG, embeddings, vector database, chunking, top-k retrieval**.

✅ Checkpoint: can you explain in 3 sentences what happens between "user asks a question" and "answer appears"?

## Phase 1: Configuration and contracts (about 1 hour)
Read these in order:
1. [src/core/settings.py](MedRAG_live/src/core/settings.py): how environment variables become settings.
2. [src/core/base.py](MedRAG_live/src/core/base.py): `ProjectConfig` and the `DocumentIngestor` contract (`load_and_parse` → `enrich_metadata`).
3. [src/projects/medrag/config.py](MedRAG_live/src/projects/medrag/config.py): the system prompt, disclaimer and collection name.
4. [src/core/projects.py](MedRAG_live/src/core/projects.py): how the name "medrag" maps to the config and ingestor.
5. [src/core/schemas.py](MedRAG_live/src/core/schemas.py): the request and response shapes.

✅ Checkpoint: if you wanted a second project (say "LegalRAG"), which files would you add?

## Phase 2: Indexing pipeline (about 2 hours)
1. [src/projects/medrag/ingestor.py](MedRAG_live/src/projects/medrag/ingestor.py) uses 3 sources:
   - PDFs in `data/guidelines/`, parsed by LlamaParse (a cloud service, so it needs a key)
   - PubMed abstracts (needs internet)
   - 4 hard-coded "bootstrap" documents, which are always added unless `MEDRAG_INCLUDE_BOOTSTRAP=false`
2. [src/core/indexer.py](MedRAG_live/src/core/indexer.py): `build_index` **deletes the collection first**, then splits text into sentence chunks (1024/100), embeds them locally with FastEmbed, and stores them in Qdrant. `QdrantClientCompat` is an adapter between versions of the libraries.

✅ Checkpoint: why can the embeddings run locally while answer generation needs OpenAI?

## Phase 3: Query pipeline (about 2 hours)
1. [src/core/service.py](MedRAG_live/src/core/service.py): `RAGService` ties everything together.
2. [src/core/retriever.py](MedRAG_live/src/core/retriever.py): builds the LlamaIndex query engine (top_k=8, "compact" mode, optional hybrid search).
3. [src/core/generator.py](MedRAG_live/src/core/generator.py): turns the LLM output into an answer with evidence, sources and confidence.

💡 Look closely at these:
- `confidence` comes only from **how many chunks were retrieved**, not from the answer's quality. With top_k=8, the result is almost always "high".
- `evidence` is raw text snippets from the chunks. It isn't generated by the LLM.
- Hybrid mode probably won't work as written, because `_build_vector_store` doesn't pass `enable_hybrid=True`. I haven't run it, so check this when you get there.

## Phase 4: The interfaces (about 1 hour)
- [src/cli.py](MedRAG_live/src/cli.py) has the `index` and `query` commands.
- [src/api/main.py](MedRAG_live/src/api/main.py) has 8 endpoints. Notice the startup warm-up and the `RLock`.
- [src/ui/app.py](MedRAG_live/src/ui/app.py): the Streamlit UI only calls the API.
- [src/core/source_manager.py](MedRAG_live/src/core/source_manager.py) handles PDF upload, delete and list.

## Phase 5: Run it locally (hands-on)
**You'll need:** an OpenAI key. A LlamaCloud key is optional: set `MAX_GUIDELINE_FILES=0` to skip parsing PDFs.

**Option A: Docker, the easiest way** ([docker-compose.yml](MedRAG_live/docker-compose.yml))
```
copy .env.example .env      # add your keys
docker compose up -d --build
```
Then open: UI at http://localhost:8501, API docs at http://localhost:8000/docs

**Option B: Python directly, best for learning and debugging**
```
docker run -p 6333:6333 qdrant/qdrant:v1.16.2
uv sync --extra dev
uv run python -m src.cli index --project medrag
uv run python -m src.cli query "First-line hypertension therapy?" --project medrag
uv run uvicorn src.api.main:app --port 8000
uv run streamlit run src/ui/app.py
```
Also open Qdrant's dashboard at http://localhost:6333/dashboard to see your chunks and metadata.

## Phase 6: Experiment (this is where you learn the most)
Change only `.env` values, rebuild the index, and compare the answers:
- `CHUNK_SIZE` 1024 → 256
- `SIMILARITY_TOP_K` 8 → 2 (watch confidence change)
- `PUBMED_ENABLED=false`, then `MEDRAG_INCLUDE_BOOTSTRAP=false`
- Ask something off-topic, like "How do I fix a car?", and see what the app does

## Phase 7: Tests and evaluation
- Unit tests in [tests/](MedRAG_live/tests/): `uv run --extra dev pytest`
- [eval/medrag/golden_dataset.json](MedRAG_live/eval/medrag/golden_dataset.json) and [src/core/evals.py](MedRAG_live/src/core/evals.py) use DeepEval to score faithfulness and relevancy. Note that these use OpenAI and cost money.
